# Публикация изменений в GitHub

Этот документ описывает последовательность действий, которая позволит
зафиксировать изменения в локальном репозитории и отправить их в ваш удалённый
репозиторий на GitHub. Инструкция составлена для проекта библиотеки линейной
алгебры и учитывает наличие подмодулей.

## 1. Проверка состояния репозитория

Перед фиксацией изменений убедитесь, что вы находитесь на нужной ветке и
просмотрите список изменённых файлов:

```bash
git status -sb
```

Если видите лишние артефакты (например, временные файлы IDE), убедитесь, что
они добавлены в `.gitignore`, либо удалите их вручную.

## 2. Формирование коммита

1. Добавьте нужные файлы в индекс:
   ```bash
   git add <файлы-или-каталоги>
   ```
   Для добавления всех отслеживаемых изменений используйте `git add .`.
2. Создайте коммит с кратким и осмысленным сообщением:
   ```bash
   git commit -m "feat: краткое описание изменений"
   ```
   Сообщение должно отражать суть правки — это облегчает проверку истории.

## 3. Работа с подмодулями (если есть)

Если вы внесли изменения в подмодули (например, библиотека `linalg` подключена
в тестовом репозитории), выполните следующие команды внутри каталога каждого
подмодуля:

```bash
cd linalg
git add .
git commit -m "..."
cd ..
```

После этого вернитесь в корневой репозиторий и зафиксируйте обновлённые ссылки
на подмодули:

```bash
git add linalg
```

## 4. Настройка удалённого репозитория

Если вы ещё не привязывали удалённый репозиторий, добавьте его:

```bash
git remote add origin git@github.com:<ваш-логин>/<репозиторий>.git
```

Для HTTPS-адреса используйте формат
`https://github.com/<ваш-логин>/<репозиторий>.git`. Убедитесь, что у вас есть
доступ на запись в указанный репозиторий.

## 5. Отправка коммитов на GitHub

Выполните push на нужную ветку (например, `main` или `work`):

```bash
git push -u origin <имя-ветки>
```

Ключ `-u` создаёт связь между локальной и удалённой веткой, чтобы в дальнейшем
можно было вызывать просто `git push` и `git pull` без указания `origin`. При
использовании HTTPS GitHub запросит логин и персональный токен доступа.

## 6. Обновление подмодулей на GitHub

Если в проекте есть подмодули, после основного `git push` выполните аналогичные
команды внутри каталогов подмодулей, чтобы отправить их изменения. Затем
вернитесь в корневой репозиторий и отправьте коммит со ссылками на обновлённые
ревизии подмодулей.

## 7. Проверка результата

После успешного push зайдите на страницу репозитория в GitHub и убедитесь, что
новый коммит появился в истории. Если работаете с подмодулями, проверьте, что
их ревизии также обновились.

> 💡 Совет: если возникли ошибки авторизации, пересоздайте персональный токен на
> странице GitHub Settings → Developer settings → Personal access tokens, включив
> права `repo`.
